個股分析改版：三個方向

在既有的分析頁上加入當日走勢圖，並把版面改成 Yahoo 股市那種「一眼看完報價」的密度。三個方案共用同一組資料與同一套 token，差別在資訊要怎麼被排出來。

標的 台積電 2330 走勢圖資料 真實 1 分 K · 2026-08-25 271 點 09:00–13:30 色票 沿用 index.css 紅漲綠跌 台股慣例

主張

把 Yahoo 的報價頭 + 12 格統計 + 走勢圖 + 五檔整組搬過來，右欄留給 Yahoo 沒有、而這個 App 才有的我的持股損益。

適合

桌機看盤、一頁比完所有數字。既有的四個分頁（籌碼／基本面／技術面／AI）原封不動掛在下方頁籤，改版風險最低。

代價

手機上要塌成單欄，五檔與統計格會變得很長。密度高＝初次使用者要找一下重點。

當日走勢圖的資料要從哪裡來

上面三張圖用的是真的資料：2330、2026-08-25、271 個 1 分點、09:00–13:30。以下是本次實際打過的端點與結果。

端點實測結果拿得到什麼限制
mis.twse.com.tw/stock/api/getStockInfo.jsp
專案已在用（supabase/functions/stock-price）		 可用 當下這一筆報價 + 五檔 + 內外盤，約 5 秒更新 只有當下一點，沒有整條曲線。要畫一日線必須自己輪詢累積。每 5 秒 3 次請求的上限
mis.twse.com.tw/stock/api/getDailyTradeInfo.jsp 不存在 — 回傳 HTML 錯誤頁並轉址回首頁。證交所沒有公開的整日分時端點
query1.finance.yahoo.com/v8/finance/chart/2330.TW
?interval=1m&range=1d		 可用 一次回傳整條 1 分 K：timestamp[]、open/high/low/close/volume[]，以及 chartPreviousClose（昨收基準線直接有） 非官方 API，無 SLA；瀏覽器直連會被 CORS 擋，必須經 Edge Function 代理

建議：Edge Function 代理 Yahoo chart，MIS 只負責「最後一點」

這個組合不用新增任何前端相依，也不用開新的 Supabase 資料表。

  1. 擴充既有的 stock-price Edge Function（或新增 stock-intraday）：代理 Yahoo chart v8，把回應壓成 { prevClose, points: [{t, c, v}] }。CORS 與 Referer 問題都在伺服端解決，和現在代理 MIS 的作法一致。
  2. 盤中最後一點沿用 MIS。Yahoo 那條線有延遲，而 stock-price 已經每幾秒抓一次即時報價——用它去接曲線的尾端，走勢圖就是即時的。
  3. 畫圖沿用自製 SVG。專案已有 LineSeriesChart / BarSeriesChart / CandleChart，這張走勢圖是同一類東西，不需要引入圖表函式庫。上面三張圖就是純 SVG 畫的。
  4. 五日／一月／一年不必另外接。daily/{ticker}.json（Supabase Storage）已經有日 K，長天期切換直接用它；只有「一日」需要新資料源。

風險登記：Yahoo 端點無 SLA。若它掛掉，退路是「MIS 輪詢累積成當日曲線」，代價是要多一張 tick 表與一個盤中 cron——這是明顯較貴的方案，建議只在必要時做。
