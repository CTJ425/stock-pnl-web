Stock Helper · UI Design direction assessment

Three possible looks,
Draw to the point where you can make a decision

The current interface is a self-made glass quasi-object style (dark colors are preferred,backdrop-filter Frosted glass, indigo gradient accent color), all written in a single 2,380 conductive sources/src/index.css. The advantage is token The degree of culturalization is already very high, Most of the time when changing the design system, :root Variable; the disadvantage is that there is no standard to compare with, and every time you add a component, you are reinventing it.

The following three directions are not color replacements. —— The layout skeleton, navigation position, table density, and button shape are all different.， Because that's the real difference between these three design systems. The content uses real pictures, real columns, and real numbers.

About red rise and green fall

The native semantic color of the three systems is "green" = Forward, red = "Negative", which is contrary to Taiwan's market reading habits. All three manuscripts used it in reverse, and each selected the red and green in the color scale of the system. It should be noted that Stripe Is bright bottom: green from #10b981 pressed to #0a7d5b、 red from #ef4444 pressed to #cd1f43, can it be maintained on a white background 4.5:1 text comparison. existing formatters.ts Already fixed in front of the positive and negative values + / −， So even if a color-blind reader can't tell the difference between red and green, the numbers themselves can still be read. —— This habit should be retained in all three directions.

How to choose

There is no absolute superiority or inferiority among the three directions. The difference lies in "this app What hurts the most?" If the most painful thing is that the chip table cannot be filled, choose Carbon; If the most painful thing is that you want a set of specifications that you can rely on for a long time but don’t want to make major changes, choose shadcn； If you want an image that is completely different from the current dark glass style, choose Stripe。

shadcn/ui

Changes are minimally expensive. existing index.css Already complete token change(--surface / --border / --ink That whole set), replace :root color, Bundle backdrop-filter Remove the gradient and fillet the corners from 14px receive 8px, there are eight images. The trade-off is that it's pretty low-key —— Without the current layer of glass texture, the picture will become very quiet.

Change scope Just move index.css variable area and a few rules

IBM Carbon

It has the highest information density and is most suitable for tables with many columns such as chip tables, margin trading, and monthly revenue. How many things can be added to the same screen height? 4–5 List. but 0 Rounding the corners will make the whole thing stiffer. And the guide should start from the horizontal level tab Change to left column —— AppShell.tsx of TabNav and 720px The following .bottom-nav All have to be rewritten, which is the largest amount of work among the three.

Change scope index.css + AppShell Navigation structure reworked

Stripe FinTech

The image has changed the most, and it is most like "a financial product that sells money." But it is bright bottom: Current chart color (chartColors.ts Six of them are written to death hex,for html2canvas Deliberately not eating CSS variable) All have to be picked again,PDF remitted .report-surface Override rules can be removed instead —— because the whole app It was already bright.

Change scope index.css + chartColors.ts + Remove report-surface

One thing in common

No need to move in any three directions sources/src The component structure of —— this app of CSS yes class guide, no inline style, so changing the design system is essentially changing a copy index.css。 Carbon is the only exception (the navigation structure needs to be changed). What really needs to be decided first is: Should we give up dark color priority?。Stripe The direction is equal to the answer "yes", and the other two are equal to the answer "no".
