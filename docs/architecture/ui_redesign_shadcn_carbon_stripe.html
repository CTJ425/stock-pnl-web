股票小幫手 · UI 設計方向評估

三種可能的樣子，
畫到能做決定的程度

現在的介面是自製的玻璃擬物風（暗色優先、backdrop-filter 毛玻璃、靛藍漸層強調色）， 全部寫在單一 2,380 行的 sources/src/index.css。好處是 token 化程度已經很高， 換設計系統多半是換 :root 變數；壞處是它沒有可以對照的規範，每加一個元件都在重新發明。

下面三個方向不是配色替換 —— 版面骨架、導覽位置、表格密度、按鈕形狀都不一樣， 因為那才是這三個設計系統真正的差別。內容用的是真實畫面、真實欄位、真實數字。

版本 0.6.9 畫面 庫存總覽 · 個股分析 主題 各系統原生預設 紅漲綠跌 三個系統一律保留

Radix Primitives + Tailwind · Vercel / Linear 一脈

shadcn/ui

中性 zinc 灰階、1px 細線、幾乎不用陰影。設計的重量全部壓在字體排版與留白上， 顏色只在「真的有語意」的地方出現。主要按鈕是反白的 —— 純白底、黑字， 這是它最好認的特徵。

關於紅漲綠跌

三個系統的原生語意色都是「綠 = 正向、紅 = 負向」，跟台灣看盤習慣相反。 三份稿子一律把它反過來用，並各自挑該系統色階裡的紅綠。 要注意的是 Stripe 是亮底：綠色從 #10b981 壓到 #0a7d5b、 紅色從 #ef4444 壓到 #cd1f43，才能在白底上維持 4.5:1 的文字對比。 現有的 formatters.ts 已經在正負值前面固定加 + / −， 所以就算色盲讀者分不出紅綠，數字本身仍讀得懂 —— 這個習慣三個方向都要保留。

怎麼選

三個方向沒有絕對高下，差別在於「這個 app 最痛的是什麼」。 如果最痛的是籌碼表塞不下，選 Carbon；如果最痛的是想要一套能長期依賴的規範但不想大改，選 shadcn； 如果想要一個和目前暗色玻璃風徹底不同的形象，選 Stripe。

shadcn/ui

改動成本最低。現有 index.css 已經是完整 token 化（--surface / --border / --ink 那一整套），換掉 :root 的顏色、 把 backdrop-filter 與漸層拿掉、圓角從 14px 收到 8px，就有八成像。 代價是它相當低調 —— 少了現在那層玻璃質感，畫面會變得很安靜。

改動範圍 只動 index.css 的變數區與少數幾條規則

IBM Carbon

資訊密度最高，籌碼表、融資融券、月營收這些欄位多的表格它最適合， 同一個螢幕高度能多塞 4–5 列。但 0 圓角會讓整體變硬， 而且導覽要從水平 tab 改成左側欄 —— AppShell.tsx 的 TabNav 與 720px 以下的 .bottom-nav 都得重寫，是三者中工程量最大的。

改動範圍 index.css + AppShell 導覽結構重做

Stripe FinTech

形象轉變最大，也最像「一個賣錢的金融產品」。但它是亮底： 目前的圖表色（chartColors.ts 裡寫死的六個 hex，為了 html2canvas 刻意不吃 CSS 變數） 全部要重挑，PDF 匯出的 .report-surface 覆寫規則反而可以拿掉 —— 因為整個 app 本來就是亮的了。

改動範圍 index.css + chartColors.ts + 移除 report-surface

共通的一件事

三個方向都不需要動 sources/src 的元件結構 —— 這份 app 的 CSS 是 class 導向、 不是 inline style，所以換設計系統本質上是換一份 index.css。 Carbon 是唯一的例外（導覽結構要改）。真正要先決定的其實是： 要不要放棄暗色優先。Stripe 方向等於答「要」，另外兩個等於答「不要」。
