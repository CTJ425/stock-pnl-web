    04one day 32 Why is it not expensive?

    Every 15 It wakes up once every minute, but the actual number of external data captures is much less than 32. Four gates block unnecessary work in sequence. All judgment logic is pollPlan.ts pure function inside and nailed by tests. The cross-batch status does not need to be opened separately, but can be read directly. batch_run_log Today’s last column (readLastRun()）。

    1
    decideSkip() Today's T86 frozen and Today’s margin trading has arrived → Do nothing this round.
    Zero external requests
    skip_reason = 'complete'
    2
    nextT86State() TWSE from 16:00 Starting from every 15 Minutes will be rewritten T86. Only if the fingerprints are the same twice in a row will it be determined to be frozen. —— Comparing only once will regard the interim value as the final version.
    t86_frozen Only then allowed to call it a day
    3
    MAX_RUNS_PER_DAY = 40 Hard cap. The schedule itself will only trigger on one day 32 this time, this 8 This margin is left for manual triggering and retries.
    Stop if exceeded
    skip_reason = 'run-cap'
    4
    runSignature() Bundle {dataYmd, t86, margin, borrow, tickers} Press it into a signature. Same as the previous round, there will be no rewriting of reports and no clearing of old files.
    regenerated = false
